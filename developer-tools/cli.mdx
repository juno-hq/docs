The Scott CLI captures the live transcript of your coding-agent session — Claude Code or Codex — and publishes it to a planspace your team can review and iterate on.

## Install

The install script bootstraps the CLI, the Claude Code plugin, and (on macOS) the Scott desktop app:

```bash
curl -fsSL https://tryscott.ai/install | sh
```

You'll be asked which surfaces to install (CLI, desktop, or both) and prompted to confirm your early-access email. The CLI binary lands at `~/.local/bin/scott` and the plugin is wired into Claude Code automatically when `claude` is on your PATH.

## Commands

### `scott login`

Authenticate the CLI by minting a scoped, revocable token tied to your Scott account. Opens a browser and runs through a loopback handshake; falls back to a paste flow with `--paste` if your environment can't open a browser.

```bash
scott login
```

The token is written to `~/.config/scott/auth.json` (mode 0600). It's the same credential the MCP server and the Claude Code plugin read — so you only run `login` once per machine.

### `scott push`

Publish the current conversation to a new planspace. The CLI prefers the live transcript on disk (`~/.claude/projects/...`) so the planspace gets verbatim wording.

```bash
scott push
```

You'll get back a URL to open the planspace in the desktop or web app.

Run with `--from-conversation` to force the literal-transcript path, or pipe markdown on stdin to publish a hand-composed doc:

```bash
cat my-spec.md | scott push --title "Auth migration"
```

### `scott revoke`

Revoke this machine's CLI token and remove the local credential file.

```bash
scott revoke
```

If the local token can't self-revoke (CLI tokens can't manage CLI tokens — that's by design), the command will direct you to revoke from `https://app.tryscott.ai/settings?tab=cli`.

### `scott logout`

Forget the locally stored token without revoking it server-side. Useful for switching machines without invalidating CI credentials.

```bash
scott logout
```

### `scott mcp`

Run the Scott MCP server over stdio. You usually don't invoke this directly — the Claude Code plugin spawns it automatically. Exposed for non-Claude MCP clients (Cursor, Codex, Devin) that want to wire `push_to_planspace` and `push_conversation_from_transcript` tools by hand.

## Typical workflow

```bash
# One-time setup
curl -fsSL https://tryscott.ai/install | sh
# (the installer runs `scott login` for you at the end)

# In any project, after a Claude Code or Codex session
scott push
# → planspace URL; share with your team for review
```

Inside Claude Code, "push this to Scott" triggers the bundled skill instead — same flow, just routed through the MCP tool.

## FAQ

<AccordionGroup>
  <Accordion title="Where is the CLI token stored?">
    `~/.config/scott/auth.json` (or `$XDG_CONFIG_HOME/scott/auth.json` if set), mode 0600. Override with the `SCOTT_TOKEN` environment variable for one-off / CI use.
  </Accordion>

  <Accordion title="What's the difference between scott logout and scott revoke?">
    `logout` only deletes the local file — the token still works from any other machine that has it. `revoke` invalidates the token server-side as well, so a stolen laptop can't keep using it.
  </Accordion>

  <Accordion title="What conversation transcripts does push detect?">
    Currently Claude Code (`~/.claude/projects/...`) and Codex. The CLI selects the most recent session in your current working directory; pass `--cwd <path>` to override.
  </Accordion>

  <Accordion title="Can I use the CLI without the desktop app?">
    Yes. The CLI works on its own. Planspace links open in the web app at `https://app.tryscott.ai`.
  </Accordion>
</AccordionGroup>
