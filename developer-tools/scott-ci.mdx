Scott CI connects pull requests back to the planspaces that drove the work. It helps teams move review earlier in the process: planspaces capture design intent and team feedback before execution, then pull requests report back against that intent.

## Setup

1. Open your team settings in Scott
2. Install the Scott CI GitHub App for your GitHub organization
3. Select the repositories you want Scott to review and link
4. Add one or more planspace URLs to a pull request description or commit message
5. Open or update the pull request

No repo config file is required. The planspace URL is the contract between design intent and execution.

## How it works

```text
planspace (proposal, prototype, or approved design)
       ↓ planspace URL in PR description or commit message
pull request
       ↓ Scott CI GitHub App
agent-assisted architectural review
       ↓
PR comment + planspace execution feedback
```

When you open or update a PR, Scott CI looks for planspace URLs in the PR description and commit messages. If it finds one or more links:

1. Scott links the PR to the relevant planspace versions
2. It traces back through the [context flow](/planspaces/context-flows) to the [approved version](/collaboration/reviews)
3. It runs an agent-assisted architectural review against the PR using the planspace context
4. It leaves a GitHub comment with the review and links back to the planspace
5. When the code lands, Scott feeds the execution context back into the document set

<Tip>
  When `scott push` prints the planspace URL, paste it into your PR description or include it in a commit message on the branch. Scott CI takes it from there.
</Tip>

## Why this matters

Traditional code review asks, "Is this diff acceptable?" Scott CI asks the earlier question: "Does this implementation match the design intent the team reviewed?"

That creates a feedback loop for your team's document OS:

1. `scott push` captures proposals and prototypes as planspaces
2. teammates comment and approve direction before implementation hardens
3. PRs link back to one or more planspaces
4. Scott reviews the PR against the original intent
5. landed code updates the context around what was actually executed

## FAQ

<AccordionGroup>
  <Accordion title="What if I didn't include a planspace URL?">
    Scott CI only links PRs to planspaces when it can find a URL reference. Add the URL to the PR description (or amend a commit message) and re-push — Scott CI re-runs on PR updates.
  </Accordion>

  <Accordion title="Does Scott CI block merges?">
    No. Scott CI is informational — it leaves comments but does not create required status checks.
  </Accordion>

  <Accordion title="Can I use Scott CI without the rest of Scott?">
    Scott CI requires a planspace with an approved spec to link to.
  </Accordion>
</AccordionGroup>
