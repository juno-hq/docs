Context flows are what make Scott AI fundamentally different from a linear AI chat. Every planspace maintains a **directed acyclic graph (DAG)** of versions — like `git log --graph`, but for intent and design decisions instead of code.

## Overview

In most AI tools, your conversation is a flat list of messages. If you want to try a different approach, you either start over or awkwardly backtrack. In Scott, you **branch**.

Every turn in a planspace has a parent. When you reply to the latest message, you extend the current branch. When you reply to an *older* message, you create a new branch. Both branches are preserved, and you can navigate between them freely.

This means your planspace captures not just what you decided, but what you considered and why you chose one path over another.

## The versions tab

Switch to the **Versions** tab in the left panel to see the full context flow. The graph shows:

- **Nodes** — each node is a version that produced a document update
- **Edges** — parent-child relationships between versions
- **Branches** — divergent paths where someone explored a different direction
- **Color coding** — the primary branch is highlighted; older branches use distinct colors

The most recent branch appears on the right side of the graph, with older branches to the left.

## Branch off any version

To create a branch:

1. Navigate to any previous version using the Versions tab or the title dropdown
2. Type a new message in the chat input
3. Scott creates a new branch from that point — the agent responds with a fresh document version based on the context up to that turn, plus your new direction

Your original branch is untouched. You can switch between branches at any time.

## When to branch

Branching is useful when you want to:

- **Explore alternatives** — try a different architectural approach without losing the original
- **Hand off a direction** — share a branch with a teammate to develop independently
- **Revisit a decision** — go back to a point before a decision was made and take a different path
- **Compare approaches** — view two branches side by side to evaluate tradeoffs

## Multiplayer context flows

When multiple people collaborate in a planspace, each person's cursor position is visible in the context flow. You can see who is looking at which version, making it easy to coordinate:

- **Member avatars** appear next to the version each teammate is currently viewing
- If a teammate branches off your work, you see the fork appear in real-time
- Anyone with edit access can branch from any version

## Using context flows with the CLI

The `scott pull` command links your planspace's current branch tip to your local git branch. When you push changes to GitHub, [Scott CI](/developer-tools/scott-ci) traces the link back through the context flow to the approved spec — this is how Scott keeps documentation from going stale.

```bash
# Pull the planspace state to your local branch
scott pull

# Make your changes, commit, push to GitHub
git add . && git commit -m "implement auth flow"
git push origin feature/auth

# Scott CI auto-links the PR to the approved spec
```

See [CLI](/developer-tools/cli) and [Scott CI](/developer-tools/scott-ci) for the full workflow.

<Note>
**How we work at Scott.** When we're planning a feature with multiple viable approaches, we branch the context flow early. One engineer prototypes approach A on a branch while another explores approach B. Both branches stay in the planspace — the team compares them in the next review cycle and picks the direction with the strongest prototype evidence.
</Note>

## FAQ

<AccordionGroup>
  <Accordion title="Can I merge branches?">
    Not currently. Branches represent different directions for the spec. If you want to combine ideas from two branches, navigate to one and ask the agent to incorporate specific elements from the other.
  </Accordion>
  <Accordion title="Is there a limit to how many branches I can create?">
    No. Branch as much as you need. The context flow graph handles any number of branches.
  </Accordion>
  <Accordion title="Can I delete a branch?">
    No. All version history is permanent. This is intentional — the history of what was considered is as valuable as what was decided.
  </Accordion>
  <Accordion title="How is this different from git?">
    Git versions code. Scott versions intent. A git branch contains file changes; a Scott branch contains the conversation, decisions, and spec evolution that led to those file changes. They're complementary — Scott CI links the two together.
  </Accordion>
</AccordionGroup>
