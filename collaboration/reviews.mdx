Reviews bring a pull-request-style approval flow to your specs. Request a review when a version is ready for sign-off, and reviewers can approve or request changes with comments.

## Overview

Reviews are tied to a specific version of the document. When you request a review, reviewers see exactly which version you want feedback on and can leave their decision alongside comments.

The review workflow is:

1. Author requests a review, selecting reviewers from the planspace members
2. Reviewers are notified in their [For You](/notifications) inbox
3. Each reviewer submits a decision: **Approve** or **Request changes**, with an optional comment
4. The review status is tracked in the planspace sidebar

## Request a review

1. Navigate to the version you want reviewed
2. Click **Request review** in the top bar or sidebar
3. Select one or more reviewers from the planspace members
4. Add an optional message explaining what you'd like feedback on
5. Submit the request

Reviewers receive a notification with a direct link to the version under review.

## Submit a review decision

When you're a reviewer:

1. Open the planspace from the notification or your **Reviews** tab in [For You](/notifications)
2. Read the document version and any comments
3. Click **Approve** or **Request changes**
4. Add an optional comment with your feedback
5. Submit your decision

The requester is notified of your decision.

## Review states

| Status | Meaning |
|--------|---------|
| **Open** | Review is pending — waiting for reviewer decisions |
| **Approved** | All reviewers have approved |
| **Changes requested** | One or more reviewers requested changes |
| **Closed** | Author closed the review (superseded by a new version or no longer needed) |

## Reviews and Scott CI

When a review is **approved**, that version becomes a trusted reference point. [Scott CI](/developer-tools/scott-ci) can link pull requests back to the approved version, confirming that the implementation matches the signed-off intent. This is the mechanism that keeps your documentation non-stale — the spec isn't just a document someone wrote, it's an approved artifact connected to the code that shipped.
