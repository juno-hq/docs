Scott is a context system for teams working with coding agents. It keeps local agent work, team feedback, design approvals, and shipped code connected.

## Sync Chat

**Sync Chat** is your personal starting point after `scott sync`. It lets you ask across recent local coding-agent sessions, find recurring themes, and decide which threads deserve team attention.

Use Sync Chat when:

- You are onboarding Scott and want it to understand your recent work
- You need to search across Claude Code, Codex, Cursor, OpenCode, Gemini, and other local agent sessions
- You want Scott to recommend which sessions should become shared planspaces

Learn more in [Sync](/developer-tools/sync).

## Planspaces

**Planspaces** are shared workspaces for design intent. They combine a chat, a living document, source context, comments, reviews, approvals, and team membership.

Use a planspace when:

- a prototype or proposal needs feedback before implementation hardens
- engineers and non-technical teammates need one place to discuss intent
- you want an approved plan that can later be pulled into an agent thread

Learn more in [Planspaces](/planspaces/overview).

## Documents and versions

Every planspace has a document that evolves as you work with Scott. Saved versions let reviewers approve a specific state of the design, not a moving target.

Use document versions to:

- preserve the proposal that teammates reviewed
- compare intent before and after comments
- link pull requests to the exact design version they implement

Learn more in [Documents](/planspaces/documents).

## Comments, reviews, and approvals

Comments are anchored to document text. Reviews turn a document version into an approval workflow with clear reviewer state: pending, in progress, approved, or rejected.

Use reviews when:

- a plan is ready for formal feedback
- you need design approval before an agent starts execution
- you want the Scott GitHub App to compare a pull request against the approved intent

Learn more in [Reviews and approvals](/collaboration/reviews).

## Scott CLI

The CLI is how local coding-agent work moves into and out of Scott:

| Command | Purpose |
| --- | --- |
| `scott sync` | Upload recent local agent history and open Sync Chat |
| `scott push` | Turn the current agent thread into a shareable planspace |
| `scott pull <url>` | Load reviewed planspace context into a fresh agent or terminal session |

Learn more in [Scott CLI](/developer-tools/cli).

## Scott GitHub App

The GitHub App has two roles:

- **Code context** - make repositories available to Sync Chat and planspaces without persisting repository contents
- **PR design review** - link pull requests to planspaces so Scott can review implementation against approved design intent

Learn more in [Scott GitHub App](/developer-tools/github-app).
