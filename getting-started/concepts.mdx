Scott AI is built on a simple idea: the knowledge behind your code — the intent, the decisions, the tradeoffs — should be a first-class object that you can version, branch, share, and link back to implementation.

If you've used git, the concepts will feel familiar. Instead of versioning code, Scott versions the *intent and design* that drives the code.

## Core concepts

### Planspaces

A **planspace** is the primary container for collaborative work in Scott AI. Think of it as a shared, living document with superpowers.

Each planspace contains:
- A **conversation** between you (and your teammates) and Scott's agent
- A **versioned document** — the spec that evolves as you iterate
- A **context flow** — the full branching history of how the document got to where it is
- **Connected sources** — GitHub repos, files, and folders that give the agent context

Planspaces can be private (invite-only with role-based access) or public (shareable via link).

### Turns and versions

Every exchange in a planspace creates a **turn** — a snapshot of the conversation and the document at that point in time. Turns are the atomic unit of Scott's version history.

When the agent responds to your message, it produces:
- Updated conversation text
- A new **document version** with the spec changes
- A **semantic diff** showing what was added, modified, or removed

You can navigate to any previous version, see exactly what changed, and pick up from any point in the history.

### Context flows

This is where Scott diverges from a linear chat. Turns are organized in a **directed acyclic graph (DAG)** — not a flat conversation.

You can **branch** off any previous turn. When you do, the agent rewrites the document from that branch point forward based on your new direction. All branches are preserved. This means you can:

- Explore alternative approaches without losing your original path
- Let a teammate fork your spec and take it in a different direction
- Compare how the document evolved across different branches

Context flows are the thing that makes Scott fundamentally different from a chat with an AI. Your intent has history, and that history is navigable.

### Documents

The right panel of every planspace shows the **document** — the versioned spec that the agent maintains as you collaborate. Documents support:

- Rich text formatting
- Code blocks
- Mermaid diagrams
- Inline comments anchored to specific text

The document updates with each agent turn, and you can view the semantic diff between any two versions to see exactly what changed and why.

### Connected sources

Connected sources are the context that feeds into the agent's understanding of your work. You can attach:

- **GitHub repositories** — select specific branches for the agent to reference
- **Uploaded files** — PDFs, docs, code files, design specs
- **Local folders** — directories on your machine (desktop app only)
- **Google Drive** — documents from your Drive (browser only)

Sources are attached when you create a planspace and can be refreshed at any time during the conversation.

## How it fits together

Here's the typical workflow:

1. **Create a planspace** and attach relevant context (your repo, existing specs, etc.)
2. **Describe your intent** — what you want to build, the constraints, the tradeoffs
3. **Iterate with the agent** — each exchange refines the spec document
4. **Branch when needed** — explore alternatives or hand off to a teammate
5. **Review and approve** — request reviews from teammates, leave inline comments
6. **Link to implementation** — use `scott pull` to connect planspace state to your git branch, and Scott CI to auto-link PRs back to the approved spec

The spec stays alive because it's connected to the implementation at both ends — the intent that started it and the code that shipped it.
