## Start with Sync

`scott sync` is the fastest way to onboard. It uploads your recent local coding-agent sessions from the last 14 days, opens the Sync Chat view, and starts an analysis of the work Scott can now see.

```bash
curl -fsSL https://tryscott.ai/install | sh
scott sync
```

After sync finishes, open the URL printed by the CLI. Scott will take you to **For You → Sync**, where you can ask across your recent Claude Code, Codex, Cursor, OpenCode, Gemini, and other supported agent sessions in one place.

<Tip>
  Run `scott sync` from your development machine, not from a hosted browser agent. The command reads local agent history before uploading the relevant context to Scott.
</Tip>

### Add code context

Sync Chat works immediately from session history. For code-aware answers, connect GitHub from the Sync Chat source picker or the planspace composer.

1. Click **Connect repo**
2. Install the Scott GitHub App for the GitHub account or organization you want Scott to read from
3. We recommend granting access to all repositories; limiting access can cap answer quality when relevant context lives outside one repo

<Info>
  **Security note:** Scott is SOC 2 compliant. We do not persist repository contents. We fetch code only into ephemeral sandboxes when an answer needs it, and if you remove GitHub access Scott can no longer fetch that code.
</Info>

After installation, the repositories you granted access to appear in Scott's repo picker.

### Push early, pull when ready

Use `scott push` whenever an agent thread becomes a prototype, design direction, or proposal that needs team feedback. Scott turns the thread into a planspace with a readable document, the original conversation, and the context teammates need to comment before execution hardens.

1. **Explore with your agent** - prototype the design, implementation path, or product proposal in your normal coding tool.
2. **Push the thread** - run `scott push` to create a planspace and sharing document.
3. **Share the planspace** - send the URL in Slack, Linear, a design review, or a PR description.
4. **Gather feedback early** - teammates comment, ask questions, and review the planspace while the idea is still cheap to change.
5. **Pull approved context** - run `scott pull <planspace-url>` from a fresh agent thread when it is time to execute.

This shifts team execution from late code review toward early design review. The planspace becomes the shared record of what you meant to build, why the team agreed to it, and what context the next agent should carry forward.

Learn more in [CLI](/developer-tools/cli), [Sharing](/collaboration/sharing), [Reviews](/collaboration/reviews), and [Planspaces](/planspaces/overview).

### Configure PR design review

Set up the Scott CI GitHub App for your organization when you want pull requests to stay linked to the planspaces that shaped the work.

1. Open your team settings in Scott
2. Install the Scott CI GitHub App for the GitHub organization
3. Select the repositories where your team wants Scott review and PR linking
4. Add one or more planspace URLs to a pull request description or commit message

When a pull request includes planspace links, Scott connects the PR to the original design approvals and review context. The GitHub App can then run an agent-assisted architectural review against the PR and leave a comment on GitHub.

After code lands, the PR link feeds execution context back into Scott. That gives your team a continuously updating document set: original design intent, team feedback, implementation changes, and the gap between what was approved and what actually shipped.

See [Scott CI](/developer-tools/scott-ci) for setup details.

## Install Options

<AccordionGroup>

  <Accordion title="Browser use (recommended for PMs & designers)" icon="globe">
    Go to [app.tryscott.ai](https://app.tryscott.ai/login) and sign in with Google or GitHub. The browser app uses cloud sandbox execution to make it easier to collaborate with developers on their ideas.
  </Accordion>

  <Accordion title="Use Scott from your coding agent" icon="terminal">
    Run the following command to install the `scott` terminal integration. The installer wires Scott to any detected coding agents and opens a browser window for sign-in.

    ```bash
    curl -fsSL https://tryscott.ai/install | sh
    ```

    Then run the primary onboarding command:

    ```bash
    scott sync
    ```

    To turn one active coding-agent thread into a planspace for team review, say something like:

    ```bash
    # In Claude Code, Codex, OpenCode, Cursor etc.
    "push this conversation to Scott"
    ```

    Your agent will prepare the context in a form optimized for sharing, then run `scott push`. Scott prints a planspace URL you can share with teammates.

    Once your team is sufficiently aligned, you can pull the context back to a new session with all relevant team feedback:

    ```bash
    # In Claude Code, Codex, OpenCode, Cursor etc.
    "pull the project requirements from this planspace and start building -- https://app.tryscott.ai/workspace/xxxxxxx-8f6c-yyyyyy-9056-07d8ca0-zzzzz"
    ```

    Under the hood, Scott uses skills, an MCP, and the CLI to integrate with your agent and the UI.
    If the installer cannot detect your coding agent automatically, you can manually complete the setup with this command:

    ```bash
    scott setup --claude   # or --cursor, --codex, --opencode, --gemini
    ```

    See the full [CLI reference](/developer-tools/cli).
  </Accordion>

</AccordionGroup>
